A small, honest widget
for the Tailscale VPN.

tailscale-widget puts connect/disconnect, status, and account access on your home screen by talking to the official com.tailscale.ipn app — never reimplementing the VPN. Its behavior is modeled with explicit states, targets, and time-bounded phases instead of scattered flag branches.

Explicit state machines

Previously implicit flags, branches, and timers — now named states with clear transitions and guards.

1) Widget display state

WidgetState · resolveState()

WidgetRenderer.resolveState(installed, vpnActive, pendingConnect) maps inputs to one renderable state. A pending overlay wins over the observed VPN state; “not installed” wins overall.

NOT_INSTALLED • CONNECTING • DISCONNECTING • CONNECTED • DISCONNECTED 
if !installed                      → NOT_INSTALLED
if pendingConnect == true          → CONNECTING
if pendingConnect == false         → DISCONNECTING
if pendingConnect == null && vpn   → CONNECTED
if pendingConnect == null && !vpn  → DISCONNECTED
Driver pendingConnect (Boolean overlay) → observed VPN Files WidgetState.java, WidgetRenderer.java

2) Toggle & reconciliation flow

TailscaleWidgetProvider.handleToggle

Optimistic target with polling: the UI moves to the requested state immediately and is held until the tunnel actually flips, avoiding flicker while Tailscale starts.

idle / observed→ requested (pending)→ reconciling (poll)→ settled (observed)
Target
desiredActive = !isVpnActive() — explicit intent (connect vs disconnect).
Request
Send IPN broadcast and render pending (CONNECTING/DISCONNECTING).
Reconcile
Background poll every 300 ms until observed == desired or 7 s timeout.
Settle
Render with pending = null (observed state). Install-missing short-circuits to observed.

3) Account reader phases

ReaderPhase

Accessibility-driven observation and switch assistance, scoped to Tailscale’s window (com.tailscale.ipn).

IDLE_OBSERVE⇄ SWITCH_PENDING→ POST_SWITCH_SETTLE↺ 
IDLE_OBSERVE       scan 1000 ms → read login-like email, cache on change
SWITCH_PENDING     scan 400 ms  → open account card / click other profile
POST_SWITCH_SETTLE guard ~3 s   → ignore observations while UI settles
Card cooldown 800 ms Delayed refresh 2.5 s File AccountReaderService.java

4) Switch request window

SwitchRequestState

A time-bounded request flag persisted locally and consulted to enter the pending reader phase.

NONE→ PENDING→ NONE 
requestSwitch()              → NONE → PENDING (≈15 s window)
clearSwitch() or expiry      → PENDING → NONE
getSwitchRequestState()      → centralizes expiry/cleanup
Window ~15 s Storage SharedPreferences File AccountStore.java

Constraints & reality checks

Intentional limits: what the widget can know, request, and guarantee.

Not a local “truth”

  • VPN state is heuristic: Android reports an active VPN transport, not which app owns it. The widget treats it as evidence (reliable in single-VPN practice) via TailscaleController.isVpnActive.
  • No profile-switch API: Tailscale doesn’t expose account switching. The widget deep-links to Settings and, if enabled, uses accessibility to read/assist — constrained by Tailscale’s UI and timing.
  • Broadcasts are requests: connect/disconnect uses Tailscale’s own receiver actions and may be declined (signed out/re-auth); future releases could change the contract.
  • Refresh cadence: updates on tap, after toggle reconcile, and on the OS widget schedule; external changes appear on next refresh/header tap.

Build, test & pipelines

  1. Run unit tests
